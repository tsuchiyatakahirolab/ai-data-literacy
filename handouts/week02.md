# 必要なことをAIに伝える

対応スライド：第2回 v1.1

## この回で行うこと

必要な材料と条件を伝え、同じ基準で出力を比較する。

## スライドを見ながら進める

### 2. 今日は、依頼を2通り比べる

1. 短い依頼を送る。 AIがどのような内容を補うかを見る。
2. 条件を足して、もう一度頼む。 相手・材料・完成形を伝える。
3. 結果を比べる。 条件に合った点と、まだ足りない点を書く。

### 3. 今回作るのは、参加者への案内文

教育用の架空イベント 日時：2026年10月15日 13:30〜15:00 会場：4号館402教室　定員：40人 費用：無料　申込締切：10月10日 持ち物：ノートパソコン・大学アカウント

出典：assets/week04/sample_event_notice.md（架空資料）

### 4. ① まずは短く頼んでみる

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
大学のAI講習会の案内を書いてください。
```

日時・場所・費用を、AIが勝手に補っていないか確認する。

### 5. AIが知っているとは限らない

**依頼文にないこと**：誰に向けた案内か。 実施する日時と会場。 参加者が持ってくる物。

**追加する材料**：新入生に読んでほしい。 配布資料の情報を使う。 180字程度にまとめたい。

### 6. ② 資料と条件を付けて頼む

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
配布資料を使い、新入生向けの案内を
180字程度で書いてください。
日時・会場・持ち物・申込締切を入れ、
資料にない情報は補わないでください。
```

この依頼の後に、配布資料の本文を貼り付ける。

### 7. 条件は、必要なものだけでよい

- 何のため？：誰に何を伝える文章なのか。
- 何を使う？：元資料と、変えてはいけない情報。
- どんな形？：長さ、入れる項目、完成の条件。

長い定型文や、決まった5要素を暗記する必要はない。

### 8. 2つの出力を、同じ項目で比べる

| 確認すること | 短い依頼 | 条件を付けた依頼 |
| --- | --- | --- |
| 日時と会場は正しいか | 自分で記入 | 自分で記入 |
| 持ち物が書いてあるか | 自分で記入 | 自分で記入 |
| 余計な情報はないか | 自分で記入 | 自分で記入 |

うまくいった点も記録する。「悪い例」を無理に作らない。

### 9. 必要なところだけ、修正を頼む

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
会場と日時はそのままにして、
持ち物の「大学アカウント」を追加してください。
ほかの情報は変えないでください。
```

1回で条件を満たしたら、修正回数を増やす必要はない。

### 10. 長い依頼より、必要な材料を渡す

**効果を判断しにくい依頼**：完璧な案内を書いて。 プロらしく、最高の文章に。

**確かめられる依頼**：新入生向けに180字で。 日時・会場・持ち物を入れる。 資料にない内容は足さない。

### 11. どちらを採用するか決める

- [ ] 配布資料の日時と一致している。
- [ ] 必要な項目が欠けていない。
- [ ] 対象の学生が読める表現になっている。
- [ ] 採用する理由を1〜2文で説明できる。

### 12. 成果物と確認したことを残す

保存先：`week02/`

- README.md：依頼2通り・比較・採用案

AIに任せたこと／自分で確かめたこと 確認できなかったこと

### 13. 保存した版のURLを提出する

1. GitHubで変更を確定する。 更新したファイルを確認し、commitする。
2. そのcommitのページを開く。 URLに /commit/ があることを確認する。
3. 授業の提出フォームを送る。 大学アカウントで開き、Week 02を選ぶ。

ブラウザでcommitした場合、別のpush操作は不要。

### 14. 提出する前に、ここを確認する

- [ ] 2つの依頼と、出力の違いを示した。
- [ ] 元資料と照合した点を書いた。
- [ ] 不要な試行回数を増やしていない。
- [ ] 成果物のあるcommit URLを送った。

## 使用機能に制限がある場合

有料契約は必要ありません。添付機能が使えなければ本文や小さな表を貼り付け、画像やグラフを生成できなければ文章・表で同じ確認を行います。AIの利用上限や障害で止まった場合は、既に得た出力の確認まで進め、制限があったことを記録してください。機能の利用可否は採点しません。
