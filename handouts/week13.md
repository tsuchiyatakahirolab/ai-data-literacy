# 条件を確かめながら仕事を任せる

対応スライド：第13回

## この回で行うこと

複数手順の作業を条件と途中確認で管理する。

- [multi_step_planning_case.md](../assets/week13/multi_step_planning_case.md)

## スライドを見ながら進める

### 2. 今日は、予約も支払いもしない

AIには、調べ方と計画案を頼む。 実際の予約・購入・送信は行わない。 途中で何を確かめるかを、 学生が決めてから進める。

### 3. 回答を1回もらうだけでは終わらない

- 計画する：必要な情報と作業の順番を決める。
- 材料を渡す：条件と、使ってよい資料を渡す。
- 途中で確認する：条件に合わなければ該当箇所を修正する。

### 4. 課題：学生5人の半日行程を作る

13:00に京都駅を出発し、17:30に終了。 徒歩と公共交通を利用する。 交通費は1人1,500円以内。 静かな場所と、休憩を各1回入れる。 今回は、配布した架空の施設情報を使う。

移動時間・運賃・施設は練習用の設定。実際の旅行には使わない。

### 5. ① まず、進め方だけを頼む

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
この条件で半日の行程を作りたいです。
まず、必要な情報と確認する順番を示してください。
まだ行程を完成させず、
不明な条件があれば質問してください。
```

条件文と、offline_itinerary_data.mdを一緒に渡す。

### 6. 架空資料の条件を確認する

| 場所 | 利用できる時間 | 滞在条件 |
| --- | --- | --- |
| 資料館A | 13:00〜17:00 | 静かな場所／45分以上 |
| 公園B | 13:00〜18:00 | 30分以上 |
| 休憩所C | 14:00〜17:00 | 休憩／30分以上 |

各区間の移動時間と運賃は、配布資料の表を使う。

### 7. ② 資料の範囲で行程を作る

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
配布した架空の施設情報と移動表だけを使い、
行程を作ってください。
出発・到着・滞在・移動時間と交通費を示し、
待ち時間も含めて17:30までに戻れるか確認してください。
```

資料にない近道、運賃、営業時間を補わせない。

### 8. 作成例を、自分でも検算する

13:00：京都駅を出発
13:30–14:15：資料館A：45分
14:35–15:05：休憩所C：30分
15:20–15:50：公園B：30分
16:20：京都駅へ戻る

架空の移動表に基づく例。交通費は1人920円。

### 9. 条件を、1つずつ照合する

| 条件 | 作成例の確認結果 |
| --- | --- |
| 17:30までに終了 | 16:20に戻る |
| 交通費1人1,500円以内 | 920円 |
| 静かな場所を含む | 資料館Aに45分 |
| 休憩を含む | 休憩所Cに30分 |

AIの「条件を満たします」だけで済ませず、表を読んで確認する。

### 10. ③ 条件が変わった部分だけを直す

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
資料館Aで60分過ごす条件に変更します。
ほかの条件は維持してください。
変わる時刻だけを更新し、
交通費と終了時刻をもう一度確認してください。
```

何が変わり、何が変わらないかを自分でも見る。

### 11. 実際の外出へ使う場合は、確認が増える

**この授業の基本課題**：架空資料の範囲で 時間と費用を確かめる。 実行はしない。

**発展課題：現実の計画**：行く日を決める。 運行・営業情報を確認する。 予約や支払いは人が判断する。

### 12. AIに任せた範囲を説明する

- [ ] 作業の順番を確認してから進めた。
- [ ] 時刻・費用・滞在条件を検算した。
- [ ] 資料にない情報を混ぜていない。
- [ ] 予約・購入・送信を行っていない。

### 13. 成果物と確認したことを残す

保存先：`week13/`

- README.md：行程・条件チェック・変更案

AIに任せたこと／自分で確かめたこと 確認できなかったこと

### 14. 保存した版のURLを提出する

1. GitHubで変更を確定する。 更新したファイルを確認し、commitする。
2. そのcommitのページを開く。 URLに /commit/ があることを確認する。
3. 授業の提出フォームを送る。 大学アカウントで開き、Week 13を選ぶ。

ブラウザでcommitした場合、別のpush操作は不要。

### 15. 提出する前に、ここを確認する

- [ ] 元の行程と変更した行程を残した。
- [ ] 1人あたりの交通費を確かめた。
- [ ] 架空設定の計画と明示した。
- [ ] 成果物のあるcommit URLを送った。

## 使用機能に制限がある場合

有料契約は必要ありません。添付機能が使えなければ本文や小さな表を貼り付け、画像やグラフを生成できなければ文章・表で同じ確認を行います。AIの利用上限や障害で止まった場合は、既に得た出力の確認まで進め、制限があったことを記録してください。機能の利用可否は採点しません。
