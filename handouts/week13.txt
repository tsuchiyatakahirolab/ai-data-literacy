# AIの作業を条件に照らして確かめる

対応スライド：第13回

## この回で行うこと

複数手順の作業を条件と途中確認で管理する。

## 使用する資料

- [multi_step_planning_case.md](../assets/week13/multi_step_planning_case.md)
- [offline_itinerary_data.md](../assets/week13/offline_itinerary_data.md)

## スライドを見ながら進める

### 2. 授業では行程の計画まで行う

AIに作業の順番と行程案を相談する。 確認する条件を自分で決めてから進める。 この授業では計画の作成までとし 予約・購入・送信は行わない。

### 3. 作業を分けて途中で確認する

- 計画する：必要な情報と作業の順番を決める。
- 材料を渡す：条件と、使ってよい資料を渡す。
- 途中で確認する：条件に合わなければ該当箇所を修正する。

### 4. 学生5人の半日行程を作る

13:00に京都駅を出発し、17:30に終了。 徒歩と公共交通を利用する。 交通費は1人1,500円以内。 静かな場所と、休憩を各1回入れる。 今回は、配布した架空の施設情報を使う。

移動時間・運賃・施設は練習用の設定。実際の旅行には使わない。

### 5. ① 作業の進め方を相談する

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
この条件で半日の行程を作りたいです。
まず、必要な情報と確認する順番を示してください。
まだ行程を完成させず、
不明な条件があれば質問してください。
```

条件文と、offline_itinerary_data.mdを一緒に渡す。

### 6. 配布資料の利用条件

| 場所 | 利用できる時間 | 滞在条件 |
| --- | --- | --- |
| 資料館A | 13:00〜17:00 | 静かな場所／45分以上 |
| 公園B | 13:00〜18:00 | 30分以上 |
| 休憩所C | 14:00〜17:00 | 休憩／30分以上 |

各区間の移動時間と運賃は、配布資料の表を使う。

### 7. ② 配布資料で行程を作る

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
配布した架空の施設情報と移動表だけを使い、
行程を作ってください。
出発・到着・滞在・移動時間と交通費を示し、
待ち時間も含めて17:30までに戻れるか確認してください。
```

資料にない近道、運賃、営業時間を補わせない。

### 8. 作成例の時間と費用を確かめる

13:00：京都駅を出発
13:30–14:15：資料館A：45分
14:35–15:05：休憩所C：30分
15:20–15:50：公園B：30分
16:20：京都駅へ戻る

架空の移動表に基づく例。交通費は1人920円。

### 9. 条件を一つずつ照合する

| 条件 | 作成例の確認結果 |
| --- | --- |
| 17:30までに終了 | 16:20に戻る |
| 交通費1人1,500円以内 | 920円 |
| 静かな場所を含む | 資料館Aに45分 |
| 休憩を含む | 休憩所Cに30分 |

AIの「条件を満たします」だけで済ませず、表を読んで確認する。

### 10. ③ 変更の影響を確かめる

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
資料館Aで60分過ごす条件に変更します。
ほかの条件は維持してください。
変わる時刻だけを更新し、
交通費と終了時刻をもう一度確認してください。
```

変更した条件が時刻や費用にどう影響するか確かめる。

### 11. 架空の演習と実際の計画の違い

**この授業の基本課題**：架空資料の範囲で 時間と費用を確かめる。 実行はしない。

**発展課題：現実の計画**：実施日を決めて運行・営業情報を確認する。 予約や支払いは人が判断する。

### 12. AIに任せた範囲の確認

- [ ] 作業の順番を確認してから進めた。
- [ ] 時刻・費用・滞在条件を検算した。
- [ ] 資料にない情報を混ぜていない。
- [ ] 予約・購入・送信を行っていない。

### 13. 成果物と確認記録を保存する

保存先：`week13/`

- README.md：行程・条件チェック・変更案

AIに任せたこと／自分で確かめたこと 確認できなかったこと

### 14. READMEの編集を保存する

1. 自分のPrivateリポジトリで `week13/README.md` を開きます。URLの所有者が自分のusernameか確認します。
2. 鉛筆ボタンで編集し、成果物と自分が確認したことを記録します。
3. **Commit changes** を押し、確認画面でも保存を確定します。ファイル表示に戻り、変更した内容が見えたら完了です。

![鉛筆ボタンの位置。公式文書の表示例](../assets/setup/screens/edit-file-edit-button.png)

### 15. Code画面から保存履歴を開く

自分のリポジトリの **Code** を開き、ファイル一覧の上にある時計マークと **Commits** を押します。Commitsという見出しの一覧が開くことを確認します。数字は保存回数で変わります。

![Code画面のCommitsへの入口。公開テンプレートの表示例](../assets/github-handson/week-submission-history-entry.png)

### 16. 提出するcommitを選ぶ

最後に保存した内容の見出しを押し、日時と本文を確認します。**Commit** と英数字が表示された詳細画面が開いたら、目的の版か照合します。短い英数字だけを提出しないでください。

![保存履歴の一覧。公開テンプレートの表示例](../assets/github-handson/week-submission-commit-list.png)

### 17. 提出する版の内容とURLを確認する

1. **Browse files** でその版の `week13` を開き、READMEや成果物のファイルを確認します。
2. ブラウザの戻る操作でcommitの詳細画面へ戻ります。
3. Windowsは **Ctrl+L → Ctrl+C**、Macは **Command+L → Command+C** でアドレスをコピーします。
4. URLに **`/commit/`** があり、所有者が自分であることを確認します。
5. 授業の提出フォーム（Week 13を選択）で、そのURL全体を送信します。送信完了画面まで確認します。

![commitの詳細とBrowse files。公開テンプレートの表示例](../assets/github-handson/week-submission-commit-detail.png)

初回登録にはリポジトリURL、週次・最終課題には提出内容が含まれるcommit URLを使います。画面例の教員用公開テンプレートを、そのまま提出しないでください。

### 18. 提出前の確認

- [ ] 元の行程と変更した行程を残した
- [ ] 1人あたりの交通費を確かめた
- [ ] 架空設定の計画と明示した
- [ ] 成果物のあるcommit URLを送った

## 使用機能に制限がある場合

有料契約は必要ありません。添付機能が使えなければ本文や小さな表を貼り付け、画像やグラフを生成できなければ文章・表で同じ確認を行います。AIの利用上限や障害で止まった場合は、既に得た出力の確認まで進め、制限があったことを記録してください。機能の利用可否は採点しません。
