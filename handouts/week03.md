# 変更を確かめてGitHubへ残す

対応スライド：第3回 v1.3

## この回で行うこと

GitHub上で編集と差分確認を行い、提出時点をcommit URLで示す。

## 使用する資料

- [github_onboarding_student.md](../docs/github_onboarding_student.md)
- [practice.txt](../assets/week03/practice.txt)

## スライドを見ながら進める

### 2. 今日は、3つの操作をつなげる

- 編集する：短い文章を追加し、修正する。
- 差分を見る：変更前と変更後を比べる。
- 版を示す：commit URLを提出する。

### 3. GitとGitHubの役割を分ける

**Git**：ファイルの変更履歴を 記録する仕組み。 commitで版を確定する。

**GitHub**：Gitで管理するファイルを ネット上に置くサービス。 ブラウザからも編集できる。

### 4. 同じファイルでも、版が変わる

1. 初めの版：AIで説明を作る
2. 修正した版：出典で確認した
内容を加える
3. 提出した版：読み直して、
提出する版を決める

履歴があることだけで、内容の正しさや作業の本人性は証明できない。

### 5. 自分のweek03を開く

1. 教材本体ではなく自分の保存先を開く。
2. week03を開く。
3. README.mdを
編集する。

画面に出てくる名前：自分のアカウント名を確認 ／ week03 → README.md ／ 鉛筆の編集ボタン

操作図は模式図です。画面上の位置が異なっても、操作名と目的を確認してください。

### 6. まず、短い学習記録を書く

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
## AIに任せたこと
AIに用語の説明を頼んだ。
分からない点を追加で質問した。
```

ここは編集練習用の例。自分が行った内容に置き換える。

### 7. 1回目の変更を確定する

1. Previewで、
表示を確かめる。
2. 変更内容を短く書く。
3. Commit changesで
確定する。

画面に出てくる名前：メッセージ：学習記録を追加 ／ 変更内容を確認 ／ Commit changes

操作図は模式図です。画面上の位置が異なっても、操作名と目的を確認してください。

### 8. 次に、確認したことを足す

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
元の教材を開き、用語の意味を照合した。
AIの説明と一致していた。

※実際に確認した内容を、自分で書く。
```

1回目の文章を残したまま、確認の記録を追加する。

### 9. 差分で、追加した部分を確かめる

変更前：

```text
AIに用語の説明を頼んだ。
分からない点を追加で質問した。
```

追加する文：

```text
元の教材を開き、意味を照合した。
AIの説明と一致していた。
```

緑色だけで判断せず、「＋」と文章の内容を確認する。

### 10. 2回目のcommitを開く

1. 変更をもう一度
commitする。
2. 履歴を開き、
commitを選ぶ。
3. 追加した行を
確認する。

画面に出てくる名前：確認した内容を追記 ／ 変更されたファイル：README.md ／ 追加した行を確認

操作図は模式図です。画面上の位置が異なっても、操作名と目的を確認してください。

### 11. 提出するのは、右側のURL

**保存場所のURL**：github.com/自分/ai-learning  リポジトリ全体を開く。 提出した版は固定されない。

**提出した版のURL**：github.com/自分/ai-learning /commit/英数字の列  このcommitの版を示す。

模式例。英数字の列を自分で書かず、表示中のURLをコピーする。

### 12. すべての提出ファイルを確認する

1. 提出するcommitのページを開く。 この画面には、主に変更したファイルが表示される。
2. Browse filesなどから、その版を開く。 そのcommit時点のファイル全体を確認できる。
3. week03とREADMEを開く。 必要なファイルがその版に入っているか確かめる。

最後の差分に出ないファイルも、その版に含まれている場合がある。

### 13. 練習用のファイルを追加する

1. 配布されたpractice.txtを
手元に保存する。
2. week03で
Upload filesを開く。
3. ファイルを選び、
変更を確定する。

画面に出てくる名前：Add file → Upload files ／ practice.txtを選ぶ ／ 変更内容を書いてcommit

操作図は模式図です。画面上の位置が異なっても、操作名と目的を確認してください。

保存先がweek03になっているか、追加後のファイル一覧でも確認する。

### 14. READMEからファイルを開けるようにする

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
[練習ファイルを開く](practice.txt)
```

Previewでリンクを確かめ、commit後にファイルを開いてみる。

画像やPDFも同じ考え方。ファイル名と、置いたフォルダを一致させる。

### 15. ブラウザだけで保存して提出する

**ブラウザで編集**：編集 → commit。GitHub上で保存されるので、追加のpush操作は不要です。

**提出する**：最後のcommit URLをコピーし、課題のWeekを選び、既存フォームへ送ります。

### 16. ブラウザで画像と記録を保存する

1. 自分のai-learningを開きます。読む教材は教員のhandoutsです。
2. 自分のweek03を開きます。READMEの既存の見出しを残して編集します。
3. 必要なファイルをUpload filesで追加します。Previewを見て、Commit changesで保存します。

初回の画像と記録はsetup、今回の課題は自分のweek03に保存します。

### 17. ブラウザで最後のcommitを提出する

1. 自分のweek03を開き、READMEと成果物の保存を確認します。
2. 最後のcommitを開き、その版に必要なファイルがあるか見ます。
3. 表示されたcommit URLをコピーして、大学アカウントで既存の週次フォームへ送ります。

初回はrepository URL、週次は最後のcommit URLです。

### 18. よくあるつまずきを直す

- 違う保存先だった：自分の名前と、ai-learningを確認。
- Webに見えない：自分の保存先でcommit後の表示を確認する。
- 教員が開けない：自分の招待中表示と登録URLを確認する。教員は一括点検でアクセス・認証を確認する。

### 19. 成果物と確認したことを残す

保存先：`week03/`

- README.md：
変更内容と確認結果

AIに任せたこと 自分で確かめたこと 確認できなかったこと

### 20. 保存した版のURLを提出する

1. GitHubで変更を確定する。 更新したファイルを確認し、commitする。
2. そのcommitのページを開く。 URLに /commit/ があることを確認する。
3. 授業の提出フォームを送る。 大学アカウントで開き、Week 03を選ぶ。

ブラウザでcommitした場合、別のpush操作は不要。

### 21. 提出する前に、ここを確認する

- [ ] 編集前後の違いを説明できる。
- [ ] 提出したcommitでファイルを開いた。
- [ ] 自分のPrivateリポジトリを使っている。
- [ ] 成果物のあるcommit URLを送った。

## 使用機能に制限がある場合

有料契約は必要ありません。添付機能が使えなければ本文や小さな表を貼り付け、画像やグラフを生成できなければ文章・表で同じ確認を行います。AIの利用上限や障害で止まった場合は、既に得た出力の確認まで進め、制限があったことを記録してください。機能の利用可否は採点しません。

## 出典と権利

授業用架空資料は、その性質を変えずに使ってください。スライド中の操作図は実画面のスクリーンショットではありません。製品の操作名は2026年9月17日時点の公式資料を参照しています。詳しい出典はスライドのノートと[参考資料](../docs/slides_v1.1_references.md)にあります。


初回登録はrepository URL、週次提出は最後のcommit URLです。画像と短い記録はsetupへ保存し、途中参加でも同じ初回登録フォームを使います。読む教材は教員のhandouts、書く場所は自分のweek03/README.mdです。
