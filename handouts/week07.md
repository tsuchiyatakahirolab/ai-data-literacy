# 出典を開いて答えを確かめる

対応スライド：第7回 v1.1

## この回で行うこと

AIの回答を出典に照らして確認し、その対応を残す。

## 使用する資料

- [source_check_template.md](../assets/week07/source_check_template.md)

## スライドを見ながら進める

### 2. 情報は、どこから来たのだろう

- モデルが学んだ内容
- 自分が渡した資料
- Webで検索した情報
- 接続先のデータ

会話の見た目が同じでも、使った情報源は異なる。

### 3. 今日は、2つの情報を確かめる

1. 確かめる問いを決める。 更新される可能性のある、具体的な情報を選ぶ。
2. AIを入口にして出典を探す。 必要なら自分でWeb検索する。
3. 元ページを開いて照合する。 発行元・更新日・該当箇所を記録する。

### 4. 練習テーマ：GitHubの登録方法

問い① 登録したメールは、 どのように確認するのか。 問い② 既存アカウントには、 別のメールを追加できるのか。

製品の仕様は変わる。調べた日と公式ページを残す。

### 5. ① AIに調べ方を頼む

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
GitHubの公式資料を使って、
メールの確認方法と、別のメールの追加方法を
調べてください。
根拠となるページを、項目ごとに示してください。
```

Web検索機能がなければ、自分で公式資料を探してAIに渡す。

### 6. ② 出典リンクを開く

1. 回答のリンクを実際に開く。 タイトルだけで確認済みにしない。
2. 発行元を確認する。 公式GitHub Docsか、個人の解説かを区別する。
3. 答えの根拠となる箇所を探す。 ページ内検索も使い、前後の説明を読む。

### 7. URLがあることと、根拠があることは違う

**まだ確認していない**：リンクが付いていた。 公式サイトの名前だった。 AIも正しいと言った。

**確認したことが分かる**：ページの該当段落を読んだ。 メール追加の手順が AIの説明と一致していた。

### 8. 確認記録は、この4項目で残す

| 項目 | 記録する内容 |
| --- | --- |
| 確認した情報 | 何について調べたか |
| 出典と発行元 | ページのURLと公開主体 |
| 日付 | 確認日と、分かれば更新日 |
| 照合結果 | 一致・不一致・確認できず |

### 9. 出典が読めないときは、保留する

リンク切れ、閲覧制限、内容の不一致。 別の公式資料を探すか、 「この出典では確認できなかった」と書く。 URLを作り足してはいけない。

### 10. ③ 食い違いがあれば、根拠を渡して直す

そのままコピーして使えます。内容は自分の課題に合わせて変更してください。

```text
公式資料の次の箇所と、先ほどの説明が
一致していません。該当する説明だけを修正し、
確認できる内容と不明な内容を分けてください。
```

依頼の後に、確認した箇所の必要部分だけを貼る。

### 11. 2つの情報について結論を出す

- [ ] 出典を2ページ以上、実際に開いた。
- [ ] 各情報と、その根拠の箇所を対応させた。
- [ ] 確認した日付を残した。
- [ ] 不一致や未確認の点を隠していない。

### 12. 成果物と確認したことを残す

保存先：`week07/`

- README.md：問い・答え・確認記録

AIに任せたこと／自分で確かめたこと 確認できなかったこと

### 13. 保存した版のURLを提出する

1. GitHubで変更を確定する。 更新したファイルを確認し、commitする。
2. そのcommitのページを開く。 URLに /commit/ があることを確認する。
3. 授業の提出フォームを送る。 大学アカウントで開き、Week 07を選ぶ。

ブラウザでcommitした場合、別のpush操作は不要。

### 14. 提出する前に、ここを確認する

- [ ] 2つの情報を元ページで照合した。
- [ ] URLだけでなく確認結果も書いた。
- [ ] 検索できない場合は代替の手順を記録した。
- [ ] 成果物のあるcommit URLを送った。

## 使用機能に制限がある場合

有料契約は必要ありません。添付機能が使えなければ本文や小さな表を貼り付け、画像やグラフを生成できなければ文章・表で同じ確認を行います。AIの利用上限や障害で止まった場合は、既に得た出力の確認まで進め、制限があったことを記録してください。機能の利用可否は採点しません。
