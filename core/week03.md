# Week 03: GitHubで学習記録を残す

[English](../en/core/week03.md)

## v1.3の演習手順

この回の操作手順、コピー用の依頼文、確認表は[演習シート](../handouts/week03.md)にあります。スライドと同じ順番で進められます。

## 目的

GitHubを、成果物と変更履歴を残し、提出時点を固定するための道具として使う。

## 今日の問い

AIで作った成果物は、完成版だけを見ると途中の判断が分かりにくい。GitHubを使うと、何をいつ変更したかをどのように残せるのかを体験する。

## 使用する資料

- [`docs/github_onboarding_student.md`](../docs/github_onboarding_student.md)

## 授業内で行うこと

1. Git、GitHub、repository、commitの違いを確認する。
2. 初回に用意したprivate repositoryで指定のREADMEを編集する。未設定の場合は導入手順を先に行う。
3. 変更をcommitし、repository URLとcommit URLの違いを確認して提出する。

## 課題

自分のprivate repositoryでREADMEを編集し、確認内容を追加した前後の差分を確かめる。最終版のcommit URLを提出する。

## READMEに書くこと

```markdown
# Week 03: GitHubで学習記録を残す

## 成果物
今回作成した成果物を置く。画像、PDF、CSV、グラフを作った場合は同じフォルダに置いてリンクする。

## 使用したAI
使用したAIサービス名を書く。モデル名が分からない場合は「不明」でよい。

## 使用した機能
対話・説明、Web検索・調査、資料読解、画像理解、データ分析、画像生成・編集、音声、複数手順の実行などから、実際に使ったものを書く。

## AIに任せたこと
AIに依頼した作業を2～4文で書く。

## 自分で確認・修正したこと
AI出力のどこを確認し、何を直したかを3～5文で書く。

## 残った問題
確認できなかったこと、うまくいかなかったことがあれば書く。
```

## 提出方法

`week03/README.md` を更新し、必要なファイルを同じフォルダに置く。変更をcommitし、Google Formにcommit URLを提出する。

推奨 commit message: `week03-submission`

## 確認チェックリスト

- [ ] 課題で求められた成果物を置いた。
- [ ] AIに任せたことを書いた。
- [ ] 自分で確認・修正したことを書いた。
- [ ] 個人情報や非公開情報を含めていない。
- [ ] repository URLではなくcommit URLを提出した。

## ファイルの追加も練習する

配布された[practice.txt](../assets/week03/practice.txt)を自分のweek03フォルダへアップロードし、README内から開けるリンクを付けます。操作手順は[演習シート](../handouts/week03.md)にあります。画像やPDFの提出にも使う操作です。

この回のGitHub操作はAIを使わずに行っても構いません。その場合は「AI不使用」と記録し、自分で行った変更と確認を書いてください。


初回登録はrepository URL、週次提出は最後のcommit URLです。画像と短い記録はsetupへ保存し、途中参加でも同じ初回登録フォームを使います。読む教材は教員のhandouts、書く場所は自分のweek03/README.mdです。
