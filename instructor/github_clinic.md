# GitHub操作補習の進行メモ

目安は30分です。アカウント登録や認証に時間がかかる学生には別途支援し、時間内の完了を成績条件に追加しません。使う資料は[操作スライド](../slides/GitHub_Hands_On_JA.pptx)、[学生用手順](../handouts/github_hands_on.md)、[音声・字幕付き動画](../videos/github/README.md)です。

## 授業前

授業ページに「読む教材」「学生用ひな形」「初回登録」「今週の週次フォーム」を名前付きで並べます。この授業で招待するusernameを示し、例の`tsuchiyatakahirolab`は自分の授業の担当教員へ差し替えます。練習で編集する回のフォルダを一つ指定し、学内フォームURLは公開教材に入れません。

## 進め方

| 目安 | 教員の実演と学生の操作 | 次へ進む前の確認 |
|---|---|---|
| 0～3分 | 自分の現在地を選ぶ。アカウント、自分の保存先、保存、招待、提出のどこで止まったか | すでに作成・記入した学生は同じ保存先を開いている |
| 3～10分 | 操作01～05。実演を1操作で止め、学生が同じ操作をする | 本人が開いた画面でOwner、自分のPrivate、フォルダ一覧を確認 |
| 10～18分 | 操作06～09。既存文章を残して1行追記、Preview、保存確認画面、最後の保存、開き直し | 編集欄の外に追記が残っている。ここで全体を止めて支援 |
| 18～23分 | 操作10。教員のusernameを照合して招待 | Collaborators一覧で招待中・受理済みを分けて確認 |
| 23～30分 | 操作11～15。Code、時計の履歴、最新commit、Browse files、commit URL、週次フォーム | 必要ファイルを含む版とフォーム完了を別々に確認 |

動画は一度に全部流さず、場面ごとに一時停止します。完了した学生には自分の画面で目印を示してもらい、詰まった学生を支援してから先へ進みます。動画の視聴自体や一律の操作速度を採点条件にしません。実演で学生の秘密や他の学生の提出を投影しません。

## よくある停止地点

- 教材のOwnerのまま：ひな形を読むことと、自分用に作成することを分けます。
- Star、Forkだけ：既存の課題を残し、保存先と権限を見て対応を決めます。むやみに削除・再作成させません。
- 鉛筆がない、変更提案になる：保存せず、Owner・ログイン・権限を確認します。
- Previewしかしていない：Commit changesの確認画面と最後の確定を実演し、開き直しまで待ちます。
- 教員にURLを送っただけ：Privateの閲覧には招待が必要です。検索後の追加確定と招待一覧まで確認します。
- 履歴が見つからない：Codeの最上位で時計と○ Commitsを拡大して示します。最新の保存説明、必要なら自分のURLに`/commits/main/`を付ける方法も案内します。
- SHAだけ、`/tree/`、教員のcommitを提出：自分の`/commit/`ページへ戻り、URL欄全体をコピーさせます。
- 「Verifiedだから提出済み」：署名の表示、GitHubの保存、招待、フォームの受付、授業の点検結果を分けます。

## 授業後の確認

学生が行った操作の目印と、教員によるPrivate保存先への実アクセス・画像・記録・登録対応の確認は分けて記録します。招待中を受理済みや技術点検合格と扱いません。既存の点検機能は認証・名簿・実アクセスの導入確認が済んだ環境で使い、運用未確認なら結果配信を約束しません。期限や過去課題の扱いは既存の授業方針に従います。

途中参加者には同じ資料を案内します。今回の補習は既存の初回準備と第3回を補うもので、別のフォーム・新しい採点回・新規の公開提出要件は作りません。

## 最後は学生本人が一通り開いて確認する

表紙付き教材は18枚です（表紙、操作01〜15、自己確認2枚）。[学生用チェックシート](../handouts/github_self_check.md)を配り、01〜08を順に開かせます。チェックは画面を見てから記入し、「未確認・手順不明」を残せるようにします。補習の最後、または授業後の確認に使い、所要時間の目安へ追加支援時間を見込んでください。

自己確認03は既存の初回準備手順で画像・記録を開きます。07・08は送信済みの受付を確認させ、不明なら教員側で確認してから対応を決めます。確認のために全員へ再登録・再提出させません。本人の自己確認と、教員の招待受理・実アクセス・登録照合を別に扱い、チェックの数を新しい成績条件にしません。
